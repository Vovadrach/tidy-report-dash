# Ясно — облік прибирання

Єдина актуальна версія **3.2.0**: інтерфейс основної гілки GitHub
(`259345c`) поєднано з оновленими функціями, точними грошовими
обчисленнями та надійним збереженням.

Інтерфейс — єдина дизайн-система: поверхні розділяє тон, а не обводки;
системний шрифт; світла й темна теми; усі вибори (дата, години, оплата,
помічниці) — у нижніх листах. Опис моделі й станів —
[docs/DESIGN-SYSTEM.md](docs/DESIGN-SYSTEM.md). Структура екранів і навігація
лишилися звичні: місячна стрічка, «Звіт · ＋ · Очікую», фільтр помічниць,
українська/італійська мови.
Усі сторінки працюють через один шар даних; старі паралельні API вилучено.

## Запуск

```sh
npm ci
npm run dev
```

Для перевірки з демонстраційними даними:

```sh
VITE_DEMO=1 npm run dev
```

Робоче підключення використовує `VITE_SUPABASE_URL` і
`VITE_SUPABASE_ANON_KEY` з локального `.env` або налаштувань розгортання.

## Перевірки

```sh
npm test
npm run lint
npm run build
```

Збірка включає сувору перевірку TypeScript. Мобільні сценарії:
`node scripts/ui-smoke.mjs` при запущеному демо-сервері на порту 8080.

## Захист платежів у робочій базі

Застосувати **лише** `supabase/migrations/0004_legacy_atomic_operations.sql`
за [інструкцією](supabase/README.md), потім перезавантажити застосунок.
Оновлення працює з чинною схемою й не потребує перенесення на v3.
Номер 0004 усуває конфлікт з міграцією 0003, яка вже є в GitHub.

До застосування SQL використовується сумісний старий спосіб збереження;
повні гарантії атомарності й повторних операцій потребують оновлення БД.
У цьому середовищі оновлення перевірено локально, але до робочої бази
не застосовано через відсутність адміністративного доступу.

Докладно про точність, кеш акаунтів, чернетки та обмеження:
[шар даних](src/data/README.md).
